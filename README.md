# LMS ML Pipeline — KPMG G&PS Internship Assignment

A machine learning pipeline for a Learning Management System (LMS) that:
1. **Grades code submissions** using engineered quality metrics
2. **Triages student doubts** by topic and urgency with calibrated confidence scores
3. **Routes doubts** automatically — high confidence → auto-approve, low confidence → teacher review

## Approach & Key Decisions

### Task 1 — Grading Model
- **Dataset**: `sklearn.make_classification()` with features renamed to realistic code-quality metrics (`test_pass_rate`, `cyclomatic_complexity`, `lint_error_count`, `execution_time_ms`, `documentation_score`, `memory_usage_mb`)
- **Feature engineering**: Added a composite `risk_score = complexity × (1 + lint_errors) / test_pass_rate` to capture interaction between code structure quality signals
- **Models**: Baseline Logistic Regression vs LightGBM, compared via 5-fold StratifiedKFold CV
- **Result**: LightGBM — Test F1-macro **0.956** vs Baseline **0.929**
- **Metric choice**: F1-macro over accuracy because of class imbalance (~65/35 split)

### Task 2 — Doubt Triage Classifier
- **Dataset**: 20 Newsgroups (6 categories used as doubt topics); urgency label synthesized from topic priors + keyword signals + text length + noise
- **Text features**: TF-IDF with bigrams, 5,000 features, English stopwords removed
- **Models**: Logistic Regression for both topic and urgency classification
- **Calibration**: Applied isotonic calibration via `CalibratedClassifierCV`; Brier score improved from 0.1217 → 0.1152
- **Result**: Topic F1-macro **0.930**, Urgency F1-macro **0.631**

### Routing Logic
- Confidence-based: if `max(predicted_proba) ≥ threshold` → auto-approve, else → teacher review
- **Threshold selected via cost minimization**: assumed cost ratio of 5:1 (false auto-approval vs unnecessary review), swept thresholds 0.30–0.94, selected **0.90** as cost-minimizing threshold

## Key Differentiators

| What | Why it matters |
|---|---|
| Explicit leakage audit | Topic-only model scored 0.689 F1 (leakage floor); text model scored 0.602 — confirming urgency is mostly topic-driven, not text-driven. Flagged openly. |
| Calibration check | Raw confidence scores were overconfident; isotonic calibration applied before using scores for routing |
| Cost-based threshold | Threshold justified via expected cost function, not arbitrary 0.5 default |
| Honest synthetic-data write-up | Results demonstrate modeling rigor, not real-world accuracy claims |

---

## Limitations & Tradeoffs

- Both datasets are synthetic/proxy — results show sound modeling practice, not production-ready accuracy
- Urgency label leakage: derived partly from topic, so urgency model learns the prior more than genuine text signals
- Threshold of 0.90 yields ~6% auto-approve coverage — conservative by design given the 5:1 cost assumption
- Flask/FastAPI endpoint is minimal — production deployment would need auth, input validation, and monitoring
- No hyperparameter tuning beyond light defaults — kept intentionally simple given 24hr time constraint
